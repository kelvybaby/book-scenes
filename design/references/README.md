# Reference practice

## Purpose

References are evidence for visual grammar, implementation technique, and quality—not assets or layouts to reproduce.

For every important reference, record what is useful and what must remain distinct. Extract relationships such as pacing, depth, hierarchy, material, lighting, typography behavior, or motion cause. Do not copy exact compositions, figures, motifs, identity, text, source code, or signature interaction sequences.

## Storage

- Keep durable links and notes in this file.
- Put future raw screenshots, downloaded artwork, and private captures under `design/references/raw/` and exclude that directory from Git.
- Store project-generated concept studies with their prompts and versions, not in the raw external-reference directory.
- Prefer a small, intentional reference set over a large moodboard with contradictory aesthetics.

## Reference roles

Use separate references for separate questions:

- Composition and camera
- Architecture and climate
- Botanical form
- Light and colour
- Material and texture
- Typography and passage surfaces
- Interaction and motion
- Technical implementation and performance

Do not ask one reference to define the entire project.

## Reference-selection rule

Before adding a reference, state the question it answers. If it only says “make it look like this,” it is not yet a useful project reference.
